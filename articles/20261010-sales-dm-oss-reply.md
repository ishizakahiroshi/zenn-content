土曜の朝、Xに届いていた営業DMに返信しました。2件です。

1件は海外のAI開発ツール、もう1件は国内の転職エージェント。30分ほどで両方送って、読み返したら、2通とも自作OSSの紹介が入っていました。

受信箱を開いたはずが、こちらのREADMEを配る時間になっていたわけです。

自作で [many-ai-cli](https://github.com/ishizakahiroshi/many-ai-cli) という、AIコーディングCLI用のWebダッシュボードを作っています。複数の AI コーディング CLI を並列で走らせ、承認をブラウザ 1 タブに集約。スマホからでも。

- 何ができるかの紹介ページ: https://ishizakahiroshi.com/work.html?id=many-ai-cli
- リポジトリ（Star をいただけると励みになります）: https://github.com/ishizakahiroshi/many-ai-cli

同じ悩みを持っている方は、下記で入ります。

```sh
npm install -g many-ai-cli
many-ai-cli setup
```

`setup` は最初の1回だけです。コマンドが見つからないと言われたら、ターミナルを開き直してから試してください。

起動後の見え方は、OSで違います。

Windowsでは、`setup` がデスクトップに作る「MANY-AI-CLI」から起動します。タスクトレイのアイコンから「Hub を開く」でブラウザが開き、止めるときは同じメニューの「Hub を停止」です。

macOSとLinuxでは、デスクトップの「Many AI Hub Start」と「Many AI Hub Stop」で起動と停止をします。一緒に開くコンソールがHubの本体なので、閉じずに最小化しておきます。

ターミナルからなら、どのOSでも `many-ai-cli serve --open` で起動し、別のターミナルで `many-ai-cli stop` を打てば止まります。

起動したら、Hub UI左下の「+ 新しいセッション」から使うAI CLIを選びます。実機で確かめているのはWindowsで、ネイティブのmacOSとLinuxはREADMEでもまだ十分に検証できていない扱いです。

## 1件目：「エージェント、並列で動かしてます？」というDMでした

最初のDMは、AIコーディングエージェントを並列で動かしているか、という問いかけでした。方法を知っているからリンクを送る、と。

ところが、リンクは来ません。続けて届いたのは、製品名と短い説明でした。URLは付いていません。正直、無視かブロックかで迷いました。

プロフィールの肩書きは Growth。製品を作る人というより、広める側の人のようです。製品のほうを調べてみると、DMの説明どおり、複数のAIエージェントを並列に動かすためのIDEのようでした。

many-ai-cliは、Claude CodeやCodexなどのCLIをPTYで包んで、承認待ち・完了・エラーをHubの画面に集める道具です。IDEを作る気はなくて、いつものCLIはそのまま使い、見張り役だけを外側に足す方向で育てています。

同じ「エージェントを並べたい」でも、向こうは開発環境ごと、こちらはCLIの外側だけ。形はだいぶ違います。

違うからこそ、自己紹介する意味はあるかも。そう思いました。

## 2件目：転職は辞退して、技術の仕事の入口を置きました

もう1件は、国内の転職エージェントから。記事を読んでくれていて、題名だけでなく設計の考え方まで触れた、長いDMでした。提案は30分のキャリア面談。案内には、業務委託と正社員の両方の選択肢が入っていました。

いまはフルリモートで働いていて、勤務条件にも働き方にも満足しています。転職は考えていないので、面談は丁寧に辞退しました。

そのうえで、many-ai-cliや [Deskly](https://github.com/ishizakahiroshi/deskly) など、個人で作っているOSSを紹介しました。技術支援や業務委託の案件なら相談できる、という返事です。具体的に挙げたのは、AIエージェントの導入支援、既存業務の自動化、システムの設計・開発あたり。

下書きの段階では、やり取りは文章中心、という書き方でした。送る前に「まずDMで概要をもらい、必要なら技術的な打ち合わせにも対応する」に直しています。

![玄関先で、お互いに案内のチラシを渡し合う](/images/03_2026-10-10_sales-dm_illustration-exchange.png)

面談を断る返信に、こちらからの仕事の入口も添えた形です。お断りの文章を書き終えるころには、小さな営業案内が同居していました。

Desklyは、連絡を案件ごとに見渡して、誰の返事待ちか、次に何をするかを整理するための道具です。まだ開発中で、公開しているmainは設計資料が中心です。

## 2通を並べたら、答える順番が同じでした

書いているときは意識していませんでした。並べてみると、2通とも順番が同じです。

1. まず、相手の提案に答える（試したい／辞退します）
2. 次に、自分が何を作っているかを1〜2行で
3. 最後に、相談できる仕事の範囲

提案への答えが先にあると、相手は次に何をすればいいか迷いません。そのあとの自己紹介は、言ってしまえばおまけです。おまけの中身は、リポジトリのURLが引き受けてくれます。

:::message
今回やってみて、手元に残ったこと

- 営業DMへの返事は、相手の提案への答えを最初に書く
- 自分のことを全部DMに詰めない。説明の続きはリポジトリに置いておける
- 英会話が苦手でも、AI翻訳を使えば文章では返せる
- 返事が来るまでは、結果は分からない。分からないと書いておく
:::

これが仕事につながるのか、ツールを試すことになるのか。相手がどう受け止めたのかも、返事が来るまでは分かりません。
